# ADR-005：进程资源占用（内存 / CPU）采集与排序

- 状态：已接受（2026-09-09）
- 背景：用户希望在每个进程行看到它（及其所监听/占用端口）的内存与 CPU 占用，并能按这两项排序、默认从大到小，以便快速定位"吃资源又占网络"的进程。端口本身不消耗资源，资源归属于拥有该端口的进程，因此指标挂在进程维度。

## 决策

### Rust 侧采集（`netinfo.rs`，随 `get_processes()` 一并返回）

- **内存**：`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` 后调用 `GetProcessMemoryInfo`，取 `PROCESS_MEMORY_COUNTERS.WorkingSetSize`（物理内存工作集，字节），与 Windows 任务管理器"内存"列同一口径；前端按 MB / GB 自适应格式化。
- **CPU（两次采样增量法）**：
  - `GetProcessTimes` 取每进程累计的内核 + 用户时间（FILETIME 合并为 100ns 计数值）。
  - 用进程内全局 `Mutex<Option<CpuSnapshot>>` 记录上一次采样的墙钟时刻 `Instant` 与各 PID 累计时间；本次采样时 `CPU% =（本次累计 − 上次累计）/（墙钟间隔 × 逻辑核数）× 100`，结果 `clamp(0,100)`、保留两位小数。
  - 分母乘以 `available_parallelism()` 逻辑核数，即**任务管理器口径**（所有逻辑核总和为 100%，单核满载在 8 核机器上约 12.5%），上限 100%。
  - 首次运行没有基线，CPU 记为 0；本工具是**手动刷新**（ADR-004），相邻两次刷新天然构成两次采样，无需后台定时器。
- **降级**：对受保护进程（System/Idle、部分系统服务）`OpenProcess` 可能失败，此时内存与 CPU 均记 0，不影响其它字段；管理员运行（ADR-003）下可覆盖绝大多数进程。
- `ProcessInfo` 新增 `memory: u64`（字节）、`cpu: f64`（百分比），serde camelCase 透传到前端。

### 前端展示与排序（`ProcessList.vue`）

- 表头在 PID 之后新增 **CPU**、**内存**两列，列序为：进程 / PID / CPU / 内存 / TCP / UDP / 监听 / 端口 / 状态 / 操作。
- CPU 数值按占用做暖色分级（≥25% 红、≥8% 琥珀、其余常规灰），高占用一眼可见；鼠标悬停显示精确值，内存悬停显示原始字节数。
- **排序**：CPU、内存表头为可点击按钮（带 ↕ / ▼ / ▲ 指示）。点击新列默认降序；再次点击在降序 ↔ 升序间切换。排序状态为组件本地 `sortKey/sortDir`，**默认 `memory` 降序（从大到小）**。排序在前端对已过滤结果就地进行，不触发 IPC。

## 后果

- 资源指标与连接/进程数据在同一次快照返回，不增加 IPC 往返；CPU 依赖两次刷新间的时间差，第一次打开或刚刷新瞬间 CPU 列为 0 属预期。
- 单元测试 `test_get_processes` 守护：自身进程内存必 >1MB、所有 CPU 值落在 0–100、第二次采样能取到非零 CPU，并按内存 Top 打印人工核对。
- 采用任务管理器口径（除以逻辑核数），与用户在任务管理器中的直觉一致；若后续需要"单核 100% 封顶"口径，仅需调整分母。
